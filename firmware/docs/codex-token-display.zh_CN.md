# Codex Tokens 显示器

AI Passport 的独立 240 × 320 用量仪表盘，参考用户提供的深蓝灰界面、浅绿标签和青色进度条。
复用屏幕、按键、电池 BSP，无原版测试菜单入口。设备不保存账号凭据，不使用 Wi-Fi；可选提示音复用音频 BSP。

## 操作与统计口径

- 首页单击确定：额度总览＋Token 数 ↔ 输入／缓存／输出明细＋美元估算；再按返回。
  标题 `TOTAL TOKENS` 和主数字保持不变。
- 双击确定：按保存顺序循环已开启的页面；默认四页为**首页 → 统计页 → 系统监测 → 明信片 → 首页**，不会同时触发单击。返回首页保留原先的总览／明细模式。
- 底部只有三段细线，高亮当前页，移除操作提示文字。
- 上／下键在首页和统计页切换今日／本周／累计；模型排行榜随周期变化。
  统计页单击确定不执行操作，数量／美元和总览／明细切换属于首页。
- 右上角显示硬件电量；读取失败显示 `--%`。
  明信片左上显示时间、右上显示日期／星期，保留导入内容和页码线。
- 明信片单击确定：图片／标题／副标题 ↔ 联系二维码／名字；保留翻面状态，上下键不操作。
- USB 或 BLE 蓝牙每 5 秒同步；15 秒未收到有效数据，明确提示断线及数据过期。
- 账户额度每 60 秒读取；超过 3 分钟未更新，隐藏过期百分比并提示待更新。

Token 数来自本机 Codex 的 `sessions` 和 `archived_sessions` 日志。总量＝输入＋输出；
缓存已经包含于输入，推理已经包含于输出，不重复相加。今日、本周按电脑本地日期计算，周一为一周起点。
去除重复计数事件和分叉复制的历史事件；若第一条记录已包含继承或截断的累计历史，只计该条的最后一次请求。
删除或无法访问的日志不计入，因此累计表示可读取的本机历史，不等于全账号或跨设备终身用量，也不是账单。

额度来自已登录 Codex 的只读 `account/rateLimits/read` 接口，优先选择多额度桶中的 `codex`。
按照真实窗口时长显示“每周额度”“5小时额度”等，不假定主窗口一定是 5 小时。
没有第二窗口则显示暂无数据。重置券只展示数量，不提供消耗入口。美元金额是 Standard API 等价估算，不是订阅实际扣款或账单。
电脑端不读取或导出认证文件、不发送推理请求、不输出完整账号响应；USB／BLE 仅传统计数字、套餐类别、额度信息、活动状态枚举、估算美分及完整度标记，不传聊天内容或账号凭据。
接口来源：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。

## 美元估算

固定使用 **2026-10-16 Standard 公开 API 单价**，单位美元／百万 Token：

| 模型（官方来源） | 普通输入 | 缓存读取 | 缓存写入 | 输出 |
| --- | ---: | ---: | ---: | ---: |
| [gpt-6.1-sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) | 2 | 0.10 | 2.50 | 10 |
| [gpt-6-sol](https://developers.openai.com/api/docs/models/gpt-6-sol) | 2 | 0.20 | 2.50 | 10 |
| [gpt-6-astra](https://developers.openai.com/api/docs/models/gpt-6-astra) | 10 | 1 | 12.50 | 50 |
| [gpt-5.6-sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol) | 4 | 0.40 | 5 | 20 |
| [gpt-5.6-luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) | 0.20 | 0.02 | 0.25 | 1.20 |

单次请求输入超过 272,000 Token 时，该次请求的输入、缓存读取和写入单价乘 2，输出乘 1.5。
费用＝〔（输入－缓存读－缓存写）×普通输入价＋缓存读×读取价＋缓存写×写入价＋输出×输出价〕÷百万。
推理 Token 已包含于输出，不重复计费。内部使用整数纳美元，按所选周期汇总后只进行一次美分四舍五入。

模型来自 `turn_context`；仅当 `last_token_usage` 与计数增量一致时按该次请求估算。
未知模型、缺少缓存写入计数、缓存子集非法或不能确定单次请求的增量均不猜价格。
分叉复制历史只计一次，相同事件的完整副本可以补齐估算信息。
`部分估算` 表示还有未能计价的用量；`估算 -- / 数据不足` 表示没有可计价数据；有历史记录但该周期无用量时为 $0.00。
超过一百万美元时使用 M 缩写，以免屏幕截断。

这是按当前价格表重估本机保留的用量，不还原历史成交价。本机元数据不足以确认计费服务档位，统一以 Standard 为比较基准。
不含 Fast／Ultrafast 加价、地域加价、工具调用费用、税费和订阅费。GPT-5.6 Sol 当前为促销价，官方说明至少持续至 2026-11-21。
未来价格变化需更新 `companion/token_pricing.py` 并重新打包同步程序；新增未知模型会明确显示部分／不可用。
运行时不联网抓取价格，也不产生付费推理请求。

## 状态灯

左上角圆灯：任一新鲜额度窗口已用达到 100%，且重置时间尚未到（或未知）时亮红灯；
红灯优先于活动状态。存在正在执行的本机 Codex 任务时绿灯，待命时蓝灯；断连或未知时灰灯。
这里的额度是 Codex 账号额度桶，不是 ChatGPT 网页独立用量。小于 100 的百分比向下取整，
99.9% 不会被误判为耗尽。

活动状态读取本机 `task_started`、`task_complete`、`turn_aborted` 生命周期事件，
按任务 ID 合并分叉复制的事件。任一最近未结束任务显示绿灯，完成／中断清除活动状态。
归档日志不会触发绿灯。未结束任务连续 15 分钟没有新事件则视为未知，避免崩溃遗留日志一直亮绿灯；
超长且无日志的工具调用也可能触发灰灯。最新已知生命周期已结束则待命，缺少／无法读取生命周期则未知。
这是本地日志推断，不是跨进程实时状态接口；独立 app-server 无法代表桌面进程已加载任务的运行状态。
不会为获取状态恢复或修改任何任务。

## Windows 运行方式

双击交付的 `CodexTokenDisplay.exe`，或使用 Python 3.10 以上：

```text
python -m pip install -r companion/requirements.txt
python companion/codex_tokens.py
python companion/codex_tokens.py --dry-run
python companion/codex_tokens.py --list-ports
python companion/codex_tokens.py --transport usb --port COM7
python companion/codex_tokens.py --transport ble
python companion/codex_tokens.py --list-ble
python companion/codex_tokens.py --transport ble --ble-address AA:BB:CC:DD:EE:FF
```

额度功能需要电脑已安装并登录 Codex；账户或网络异常不影响本机 Token 统计。
程序从 PATH 或 Windows Codex 默认安装目录寻找 Codex。程序保留控制台窗口，关闭窗口或 Ctrl+C 退出。
不设置开机启动、不安装后台服务。断开后自动重试连接。
默认 `--transport auto` 优先 USB，没有 USB 时扫描 BLE；建立连接后保持当前通道，直到断线。
需要插线充电同时蓝牙同步时使用 `--transport ble`。同一设备只运行一个同步程序。
USB 自动识别限唯一的 Espressif 303A:1001；多个候选需 `--port`。
BLE 仅选择唯一匹配服务的设备，多个设备需使用 `--list-ble` 列出的 `--ble-address`。
v4 发送前必须完成 `CT_HELLO 4`／`CT_READY 4` 握手，应先升级固件再运行 v4 同步程序。
不主动切换 DTR/RTS，不调用烧录工具。

## 蓝牙服务

ESP32-C3 运行单连接 NimBLE GATT 外设，名称 `Codex Passport`。Windows 同步程序使用
Bleak 3.0.2，需要开启电脑蓝牙；程序直接连接，无需配对成传统蓝牙串口／COM 设备。

- 服务：`9e7a0001-4b51-4a4c-9b50-2f53f077c301`。
- RX 带响应写入：`9e7a0002-4b51-4a4c-9b50-2f53f077c301`。
- TX 读取／通知：`9e7a0003-4b51-4a4c-9b50-2f53f077c301`。

客户端先订阅通知，再握手；以 20 字节分包兼容最小 ATT MTU，每次快照等待应用层 ACK。
设备在断线或写入间隔超过 2 秒时清空半帧，断线后恢复广播；电脑端连接失败会重新扫描并重试。Windows 连接时重新读取 GATT 服务，
断开前明确取消通知订阅，释放连接后等待会话事件处理再关闭事件循环，避免再次订阅被系统取消。
此版无系统配对绑定和应用鉴权，适用于附近设备统计展示，不作为凭据或保密数据传输通道。
服务只接受数值快照，没有执行命令或烧录功能。

合并刷新固件后，Windows 残留的旧配对可能导致设备仍在广播，但 GATT 服务读取超时。
v3 升级时观察到此问题：重启设备未解决，仅删除 Codex Passport 的旧配对记录后恢复连接。
如果 Windows 将此设备列为已配对，删除该设备的旧配对，再由同步程序直接连接。
无需重置其他蓝牙设备，也无需为此擦除 Flash。

参考：[Bleak 客户端接口](https://bleak.readthedocs.io/en/latest/api/client.html)、
[ESP-IDF NimBLE 外设示例](https://github.com/espressif/esp-idf/tree/v5.5.3/examples/bluetooth/nimble/bleprph)。

## 第二页统计

第二页参考用户提供的模型／活动／趋势图，适配 240 × 320 屏幕，保留顶部状态灯和电量。
输入／缓存／输出明细属于首页单击模式，没有第三页。

模型区显示所选今日／本周／累计周期中用量最大的两个模型分组，数量为输入＋输出，
占比按全部模型总量计算并四舍五入到整数百分比。未知模型或缺失模型信息归入“其他模型”。
没有第二个模型时显示横线，不补造数据。

活动热图有 26 列，每列一周，列内从周一到周日；右侧为当前周。按有正数 Token 用量的日期计活跃天数，
以四档对数强度展示，当前周未来日期留空。月份标注首列、中间列和末列。
趋势线显示近 60 个本地自然日的 Token 数，按该窗口峰值缩放，峰值在上方展示；
三个日期标签分别对应首日、中间日和末日。没有日志的日期为空，不插值补造；这不是全账号跨设备活动记录。
切换统计周期只影响模型排行，热图／趋势窗口固定为近 26 周／60 天。

## USB／BLE 协议

保留 CT1（19 个整数）、CT2（20 个）、CT3（26 个）兼容，缺少统计图数据时显示等待统计，不显示伪造的零值。
旧 HELLO 1～3 握手仍有效。新版使用：
`CT4 <47个空格分隔整数> <heat> <trend>*<校验>\n`。
校验为星号之前全部字节的 FNV1a，八位小写十六进制。

前 26 字段沿用 CT3：序号；今日输入／缓存／输出；本周三项；累计三项；
第一额度已用百分比／窗口分钟／距重置秒数；第二额度三项；重置券数；套餐；额度年龄；活动状态；
今日美分／完整度；本周美分／完整度；累计美分／完整度。
活动状态：0 未知、1 待命、2 执行中。套餐：0 未知、1 Free、2 Plus、3 Pro、4 Team/Business、5 Enterprise。
费用完整度：0 不可用（美分=-1）、1 完整、2 部分（美分非负）。未知计数为 -1。

新增字段：每个周期两个模型的 ID／数量（共 12 字段）；活跃天数；三个热图月份；
三个 MMDD 格式的趋势日期；每日峰值 Token；统计有效标记 0／1。
模型 ID：0 其他／未知、1 gpt-6-astra、2 gpt-6.1-sol、3 gpt-6-sol、4 gpt-5.6-sol、
5 gpt-5.6-luna、6 gpt-6-luna、7 gpt-5.6-terra；无模型行使用 0/-1。
heat 为 182 个 0～4 强度数字，5 代表未来留空；trend 为 60 个归一化到 0～1000 的点，每点三位小写十六进制。
协议只接受有界数字，模型名称和聊天内容不会作为远程 UI 字符串发送。

有效快照回复 `CT_ACK <序号>`；超过 1023 字节丢弃到换行。覆盖快照前检查校验、字段范围、模型数量之和、日期和图表数据。
数值和图表同属一个原子快照，避免混入不同周期或序号的数据。BLE 继续使用 20 字节带响应分包及应用 ACK。
USB RX 缓冲为 2048 字节，1024 字节组帧缓冲为静态分配，不占 USB 工作任务栈。

## 浏览器明信片编辑器

运行 `CodexTokenDisplay.exe --postcard-editor`，或交付包中的 `open-postcard-editor.cmd`。
程序在随机 localhost 端口仅提供四个内置静态文件，并打开默认浏览器；Windows 下使用 Chrome／Edge 的
Web Bluetooth 或 Web Serial。浏览器设备选择由用户点击触发。没有云账号、CDN、外部网站或图片上传服务器。
实现参考：[Chrome 蓝牙文档](https://developer.chrome.com/docs/capabilities/bluetooth) 和
[ESP-IDF 分区接口](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/storage/partition.html)。

先退出用量同步程序释放连接，再点“搜索蓝牙设备”或“连接 USB”选择 Passport。
选择图片、标题、可选副标题、二维码图片、联系名字；网页预览即导入排版，过长文字会缩小或裁切至预览区域。

### 存储与传输约定

本应用将 factory 大小调整为 `0x770000`（起点 `0x10000`），保留 `postcard` 数据分区，子类型 `0x40`，
范围 `0x780000..0x7FFFFF`，共 512 KiB；NVS／PHY 起点不变。
两槽各 256 KiB，前 4096 字节放头部，其后保存两面共 253440 字节 RGB565。
图片直接映射 Flash，不占用整图内部 RAM。后台任务擦写非活动槽，验证 FNV-1a 后最后写入有效标记；
在 BSP LVGL 锁内切换图像指针后，旧槽才允许重用。启动校验两槽并选择最新有效内容。
合并固件及正常应用刷写不包含预置明信片；全片擦除或不兼容的新分区布局会删除内容。

USB／BLE 共用换行命令，与 CT1–CT4 共存：`PC_HELLO` 返回 `PC_READY 1`；
`PC_TIME 本地午夜后秒数` 返回 `PC_TIME_OK`，兼容旧客户端，仅显示时间；
v5 `PC_CLOCK 本地民用时间按 UTC 编码的秒数` 返回 `PC_CLOCK_OK`（2000–2099 年），
例如浏览器 `Date.UTC(年, 月索引, 日, 时, 分, 秒)/1000`，不再在设备端换时区。上传命令为 `PC_BEGIN id fnv32`、
`PC_DATA id 原始字节偏移 hex_rle`、`PC_DONE id`、`PC_STATUS`。
上传回复 `PC_STATE id 状态 已收原始字节数`，状态 1 排队／忙、2 接收中、3 已提交、4 失败。
网页轮询到 2／3，验证每段偏移，仅状态 3 报告成功；乱序／重复片段不会增加偏移。
每帧小于 1024 字节，每块解压最多 256 字节；标签 0..127 表示 tag+1 个原始 RGB565 像素，
128..255 表示后两个字节重复 (tag&127)+1 次。BLE 每次写 20 字节，兼容最小 ATT MTU。
Flash 操作在后台任务执行，不在按键／蓝牙回调中执行。

新增主机测试：`tests/test_postcard.c` 注入上传中断、校验失败、擦写失败、顺序错误，验证重启恢复及跨午夜走时；
`tests/test_postcard_browser.py` 在无头 Chromium 中模拟 USB／BLE，使用真实编辑器导入文件，
将压缩结果逐块交给 `tests/postcard_codec_probe.c` 解码核对。这些不等于真实蓝牙或二维码实机验收。
