# Assets

This directory stores reusable fonts, images, music, and sound effects, organized by asset type.

Keep each asset in the matching subdirectory and document its destination, naming, integration method, and source/license. Do not mix binary assets with Markdown documentation.

## Fonts

Store reusable font files and generated font sources in `fonts/`.

Codex Token Display uses `fonts/NotoSansCJKsc-Regular.otf` from
[Noto CJK](https://github.com/notofonts/noto-cjk), licensed under the included
`fonts/OFL.txt`. `tools/token_font.py` generates the 14px PLAIN 4bpp
`fonts/token_font_14.c` and a Unicode/hash inventory. Only the generated subset
is linked into the firmware; the full OTF is a reproducible source asset.
See [application documentation](../docs/codex-token-display.md) for verification.

- Use descriptive names that include the family, weight, size, and format when relevant.
- Document the source, license, character range, conversion command, and expected destination.
- Check Flash and internal-RAM impact before adding a font; the ESP32-C3 has no PSRAM.
- Do not commit fonts whose license does not permit redistribution.

## Music and sound effects

The user-supplied `images/codex-details-reference.png` and
`images/codex-analytics-reference.png` are retained unchanged as local design
references for the Codex application, not embedded in firmware. Source: user
attachments, 2026-10-16; redistribution license unspecified. Postcard photos/QRs
are runtime imports, not embedded or saved in the source repository.

Store reusable music and sound-effect sources in `music/`.

- Document the source, license, sample rate, bit depth, channels, conversion command, and destination.
- Prefer 16 kHz, 16-bit mono PCM when it matches the current BSP audio path.
- Check Flash and internal-RAM cost before embedding audio; stream or chunk long recordings.
- Do not commit media without redistribution permission.

- `images/postcard-date-reference.png`: user-supplied date/weekday header reference (2026-10-16); reference only, not embedded in firmware; license unspecified.

- `images/postcard-default-avatar.svg` / `.png`: original symmetric default avatar (MIT), generated by `tools/create_default_avatar.py` and bundled in the web editor. The earlier supplied reference is retained as `images/postcard-avatar-reference.png` and is not the default asset.
- `images/postcard-editor-header-reference.png`: supplied previous editor header, retained as redesign reference only.
- `images/postcard_default_rgb565.c`: generated with `tools/postcard_defaults.py` from the actual editor; flash-only fallback faces, including the public editor URL QR.

## Supplied Codex notification sounds (v8)

`music/codex-notification.wav` is the user-provided completion sound (48kHz, 16-bit,
stereo, 0.570875s). `music/codex-error.wav` is the supplied quota-exhausted sound
(48kHz, 24-bit, stereo, 0.586646s). Source: user's desktop attachments, 2026-10-16;
no independent ownership or redistribution license is asserted. The originals are
kept unchanged for this requested implementation.

Run `python3 tools/convert_codex_sounds.py` (or `--check`) to create
`music/codex_sounds.c` and its hash/format inventory `music/codex_sounds.json`.
The standard-library converter averages channels, low-pass filters and decimates
to 16kHz/16-bit mono without gain, trimming or speed changes. The firmware links
37042 sample bytes into read-only Flash; a 640-byte stack buffer streams playback
through the BSP. No complete clip is allocated in RAM. Original WAV headers are
not parsed on the device. Source and output hashes are recorded in the inventory.

## Three supplied sound banks (v9)

Only creator-supplied recordings are linked: Codex completion/error WAV, OpenCode
`opencode-complete.aac` / `opencode-error.aac`, and Antigravity
`antigravityCascadeDone.mp3` / `antigravityActionRequired.mp3`. Source: user
attachments, 2026-10-16; originals retained unchanged, no independent redistribution
license asserted. Antigravity ActionRequired is used for the quota-exhausted event.

Run `python3 tools/convert_codex_sounds.py --decode --ffmpeg <FFmpeg-path>` to
decode compressed sources to canonical 16kHz mono WAV caches, then generate the
existing `music/codex_sounds.c` / JSON inventory for all three banks. `--decode --check`
verifies cached decoding with the selected FFmpeg; normal `--check` uses only Python's
standard library and validates the source/cache SHA bindings in `recording_decode.json`.
Codex's existing filtered PCM is unchanged. No manual trimming, normalization or
speed changes are applied; standard decoder padding metadata is honored.

All six clips occupy 181320 sample bytes in read-only Flash, with the same 640-byte
playback buffer. No AAC/MP3 decoder is needed on the device. The former generated
soft-double preset and all application sine synthesis have been removed.

## Supplied startup assets (v10)

`images/startup-logo.png` and `music/macos-startup.mp3` are the unchanged user
attachments supplied on 2026-10-16; ownership/redistribution license is unspecified.
`tools/convert_startup_assets.py` composites the image on black and fits its visible
artwork proportionally to 88 by 110 within a 240 by 320 canvas (v12; v10 used 180 by 224 and v11 used 96 by 119). It emits the exact
quantized preview, `images/startup-preview.png`, and flash-only `startup_assets.c`.
FFmpeg decodes MP3 offline to `music/startup.wav` (16kHz/16-bit mono); the source/cache
binding is `music/startup_decode.json`. Hashes, geometry and timing are recorded in
`images/startup_assets.json`. No manual trimming, gain or speed change is used.
The image is 153600 flash bytes and PCM 92082 flash bytes. Playback retains the
640-byte chunk buffer; neither asset needs a full runtime RAM allocation.

Asset conversion requires `python3 -m pip install -r tools/requirements-assets.txt` (Pillow 11.3.0). FFmpeg is needed only when regenerating the MP3 cache.
